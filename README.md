## How I approach the work

I start with the business question, then work through the data, the model, the validation, the analysis, and the recommendation.

I also try to be clear about limitations. If a model performs badly, I say so. If a number is an estimate rather than an observed result, I label it that way. If a data issue cannot be resolved from the available source, I document it instead of hiding it.
